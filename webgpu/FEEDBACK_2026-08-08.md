## P0 — bugs

### 1. 3D forced: large initial energy jump, independent of epsilon  ~~**CRITICAL**~~

**FIXED 2026-08-08** — `plans/FORCING_SPINUP_PLAN.md` Phase 1–3: the mechanism below was
confirmed in jax too, and `scaleWGSL` now ports `shared_physics.selfnorm_scale` (positive
root of the self-energy quadratic, lagged dt from `sc[0]`); the `hasZ` envelope weighting
was checked against `gen_refvectors3d.py` and MATCHES jax to 1e-16 rel — no second bug
there. Awaiting Alfred's on-device eps sweep.

Observed: from a quiescent forced start in `rmhd3d.html`, total energy jumps sharply at
t≈0 even for very small eps; the jump amplitude does not appear to depend on eps at all.
Suspicion: an error in the forcing calculation.

Likely mechanism (to be verified before fixing): the once-per-step normalization
(`physics.js` `scaleWGSL`, lines ~316–319) sets
`scale = clamp(2*eps / P, -smax, smax)` with `P` the lagged cross-term injection power.
From a quiescent start `P ≈ 0`, so the clamp pins `scale = smax` regardless of eps, and
the raw OU field (O(1) amplitude, eps-independent) is injected at full strength until
the fields grow enough for `P` to be meaningful. `smax` is hardwired to `1.0` in both
apps' `uiParams` (`rmhd3d.html:1748`, `rmhd2d.html:975`), so the transient is set
entirely by the OU noise normalization — exactly the observed eps-independence. Note the
jax repo has the same structural cap (CLAUDE.md: cap the scale factor, never floor P)
and a related known footgun (`cfl_every`>1 NaNs from quiescent forced starts), so the
fix should be a considered one: e.g. scale `smax` with eps, pre-scale the OU amplitude,
or ramp the forcing in — decide against the jax implementation, not independently of it.
Verify first that the 2D app does/doesn't show the same jump (same clamp structure), and
whether the jump also involves the two-plane kz envelope path (`scaleWGSL` `hasZ`
branch sums only the kz = ±2π/Lz planes — check `envelope()` weighting there).

### 2. Tearing (and possibly elsewhere): contour overlay shows the wrong potential

**FIXED 2026-08-08** — it is NOT a `cp`/`cp2` mix-up: the overlay's INK encoded the
displayed field. `devtools/contrepro.js` (new) boots the page on the stub, records every
`writeBuffer` and every (pipeline, bind-group) dispatch in order and replays them
symbolically, so "which potential is *prepared* into `cp`/`cp2`" and "which level table
*inks* it" are read off frame by frame. Across psi → phi → both → off → phi and a card
close/re-add on the same chain slot, in BOTH apps, the prepared potential and the inked
set were **always** the ones the card asked for — so `_dispCont`, `contPrep`,
`contRows`/`contSlice` and the `colorize` / `colorizeCube` bindings are all correct.

Root cause: set 0's ink was picked **per texel** from the background luminance (black over
a light background, white over a dark one). The black/white boundary is therefore the
background's `lum = 0.5` contour, i.e. a contour of the DISPLAYED quantity: at
value/autoscale = −0.10 (afmhot), 0.00 (grayscale, so the ink is literally `sign`),
+0.23 (viridis), ±0.60 (RdBu). With phi on the colour map, the psi field lines flip colour
along a contour of *phi* — the reported "psi contours reflect the sign/structure of phi",
and "sometimes" because the plain-background plate (and the 3D lines view) has no field
under the ink at all. Fix, in the shared `contInk` only (`physics.js` `DISP_SHADE_WGSL`):
set 0 inks in a FIXED cyan over a field, exactly as set 1 already inks in a fixed magenta,
and keeps pure black over the plate — which is what the automatic rule already chose on
the 0.93 plate, so plain-bg and the lines view are unchanged. Kernel byte-diff: `colorize`
(2D) and `colorize` + `colorizeCube` (3D) only, that one hunk; every physics kernel
identical (116/120 and 230/240 kernels byte-identical). If the cyan is wrong for you it is
one constant, `CONT_INK`.

Second, independent defect found by the same trace and also fixed: `contLevel`'s adapting
range (`st[0]`, `CONT_RELAX = 0.05`/frame, downwards only) was never reset when a set
*changed potential*. Switching psi → phi contours in the tearing preset left the new
potential contoured at the old one's spacing — 95× too coarse on the first frame, still 5×
after 60 — i.e. no visible contours for a couple of seconds; the reverse switch floods.
`setContLevels` (`common.js`) now remembers each set's potential (`D.contFor`) and zeroes
that set's range when it changes, which `contLevel` already reads as "no history" (it takes
the measured max outright). One shared helper, no per-app copy, no WGSL change.

Verified: `contrepro.js` fails on reverse-patched pre-fix copies (4 failures in 2D, 5 in
3D) and passes on both pages after; `bootstub.js` green on both pages (plain + preset);
`wgslparse.mjs` 360/360; `dup.py` 0 NEW clone groups (15 pre-existing, report identical at
HEAD); `names.mjs`, `checks.js` green.
Awaiting Alfred's on-device look at the new ink.

Observed: psi contours sometimes reflect the sign/structure of phi when the phi colour
map is selected. Smells like an index/bind mix-up between the two contour sets (`cp` /
`cp2`) in the shared overlay (`physics.js` ~629–670; per-card selectors
`common.js:1207–1310`, sets `DISP_PSI` / `DISP_PHI`). Reproduce on the tearing preset,
then check whether the bug is in which potential is *prepared* for each set or in which

## P1 — bugs / behavior

### 3. Auto-diss fails on KH (too low; run hits the dealias scales)

`autoDiss()` (`common.js:1735`) derives diss from the *forcing sliders'* eps even when
forcing is off ("the power you WOULD inject"). For the instability presets (KH, tearing)
that is the wrong amplitude scale: diss should be based on the amplitude and scale of
the **equilibrium** (`rEqA`, shear-layer width), not a hypothetical injection power.
General principle below (P2 item 6) subsumes this: base auto-diss on measured field
amplitude near the dissipation scale. no need to fix since P2 6 supercedes?

### 4. Spectra: lower ylim often too small — spectral slope unreadable

**FIXED 2026-08-08** — the floor is now `specFloor()` (`common.js`, beside `drawSpectrum`),
pinned to a fraction of E at a fraction of k_diss, with both read off the SPECTRUM ITSELF
rather than from eps/diss — no assumption about where the energy comes from, so forced,
decaying and instability presets all go through one rule (the P2 item 6 philosophy):
`k_d` = the first k **above the curve's own peak** at which the drawn spectrum has fallen
`SPEC_KNEE = 4` decades below the chart's peak (the dissipation fall-off is far steeper than
any inertial slope, so that crossing sits at the knee whatever the slope above it is);
`E_a` = the spectrum AT `SPEC_KFRAC = 0.5 * k_d`, still inside the cascade; floor =
`SPEC_TAIL = 3` decades below `E_a`, hard-capped at `SPEC_MAXDEC = 9` decades below the
peak, and the axis is never allowed to be narrower than one decade. A spectrum that never
falls 4 decades has no knee and simply keeps its own minimum — which is then already less
than 4 decades of range. The range-setting curves are the perpendicular ones as before, or
the parallel ones on a par-only card (`hiP == 0`), so GATE H's "1e6× louder E(k∥) does not
move the y axis" is unchanged and still passes as written.

Two things the knee walk must not do (adversarial review 2026-08-08, both fixed and
spot-checked): starting it at the **low-k end** took the crossing on the WRONG side of the
peak for any spectrum that is not falling from bin 1 — a rising `k^4` inverse cascade (peak
at the last bin) read `k_d = 1` and floored at peak×1e-3, clipping its whole rising range
out of the frame (8.6 decades of content shown in a 3.6-decade axis), and a mid-k-peaked
spectrum with a deep low-k side did the same. It now starts at each curve's own argmax, and
a curve lying **wholly** below the crossing (a series 4+ decades quieter than the loudest)
is skipped rather than allowed to drag `k_d` to its first bin. Second, the tail rule is
about the DISSIPATION range only, so the floor is the min of it and `E_pre`, the smallest
value on the LOW-k side of the peak: large-scale content (an inverse cascade, a quiet range
below the forcing shell) is demo-relevant physics and stays inside the frame, while the
hyper-dissipative tail below the peak's right-hand side is still cut. `SPEC_MAXDEC` caps
both.

Measured on a realistic forced spectrum (peak 1e-1 near the shell, k^-5/3 to k_d = 40, tail
to 1.1e-15): visible range 14.6 → **5.9 decades**, and the k = 3…40 inertial range now drops
**66 px** over its 190 px of x (was 27 px). Steep decaying k^-4 spectrum: 9.0 → 6.4 decades.
A KH/tearing-like spectrum spanning only 3.3 decades is untouched (3.9 decades of axis), a
flat spectrum gets a 1-decade axis, and the empty/`waiting…` path is unchanged. The
argmax-start + `E_pre` revision leaves every falling case bit-identical (forced 5.34,
decaying k^-4 6.40, KH-like 2.26, flat 1.00 decades of axis on the spot-check's own
synthetic curves) and only moves the cases it was written for: rising `k^4` 3.60 → **8.60**
decades (data minimum clipped → visible), mid-k peak with `E(1) = 1e-7` under a 1e-1 peak
3.60 → **6.60** (E(1) clipped → visible), two curves 6 decades apart 3.60 → **5.34** (the
quiet curve no longer steals the knee).
Verified: `checksh.js` (GATE H) all spectrum-axis checks PASS unmodified — including the
1e6× parallel-spectrum invariance — beside **one pre-existing informational FAIL** ("the
plotted bins 1..nb-1 hold essentially all the energy", nb = 5, 96.278% on the 16×16×8 3D
reference state), which is byte-identical at git HEAD and unrelated to the axis rule;
`bootstub.js` green on both pages, plain + tearing/kh/collision; WGSL byte-diff 120/120 and
240/240 identical; `dup.py` over `common.js physics.js` + the two extracted page scripts
**0 NEW clone groups** (15 pre-existing, report byte-identical at HEAD, every one of them a

## P2 — UX / controls

### 6. Auto-diss: make it a checkbox, ON by default, amplitude-based

**IMPLEMENTED 2026-08-08** — `#btnAutoDiss` is gone; `ctrlDissRow` now builds `#cbAutoDiss`
(ticked by default) and `common.js` carries the controller beside it. The rule is Jono
Squire's rmhd-gpu `rmhdgpu/auto_dissipation.py`, ported with its structure and its
defaults: `k_d = DISS_KD_FRAC(0.6) * nb * kunit` (the app's retained k⊥ max IS the
dealias, which is exactly what the ⊥ spectrum is binned to), `E_d` = the E_u + E_b lanes
summed over the log shell `k_d e^±AUTODISS_SHELL_W(0.5)`, `u_d = sqrt(2 E_d)`,
`nu_target = u_d k_d^(1-2*hyper)`, relaxed in log space by `AUTODISS_SMOOTH`(0.2) with the
per-update change capped at `AUTODISS_MAX_FACTOR`(2). The pure core is
`autoDissShellE` / `autoDissTarget` / `autoDissRelax` (state in, nu out — what the node
checks drive); the impure edge is `autoDissHook`, called from the frame loop after the
spectrum block, riding the CARDS' cached readback whenever a fresh one exists
(`autoDissCache`; the cards refresh at ~3.3 Hz, the controller at 2 Hz, so with a card
open one almost always does) and taking its own only when none does — the controller
works with the spectra chart closed, and never adds a second spectrum pass when it is
open (bootstub counts the readbacks both ways). It writes through
`dissWriteLog` → `applyControls` → `refreshDissipation`: the live path, never a rebuild.
Three deviations, all app-forced and commented at the code: the cadence is WALL CLOCK
(`AUTODISS_PERIOD` = 500 ms, 2 Hz, since the loop's steps-per-frame is adaptive and every
other readback hook here is wall-clock); `[nu_min, nu_max]` IS the slider's dynamic range
from item 7, whose ends ("Re ~ 1" and "3 decades under marginal") are exactly the window
the controller belongs in and which guarantees the slider can always show the value; and a
shell with NO measurable energy HOLDS instead of driving to nu_min, because a quiescent or
freshly-seeded IC has nothing at k_d yet and that is an uninformative measurement, not an
instruction. While ticked the slider is DISABLED and follows the controller, so unticking
leaves the manual slider exactly where the controller left it. The slider's 0.05-decade
step doubles as a dead band (an update under 0.125 decades of log distance rounds to no
change), which stops a converged controller re-uploading the dissipation array at 2 Hz.
The t=0 seed is `autoDissSeed()` = `nu_marg` = `k_1^(1/3) k_d^(2/3-2*hyper)`, the
amplitude-free marginal estimate — NOT the old eps-based formula, deliberately: its
eps^(1/3) is precisely the item-3 bug, and nu_marg lands within ~0.3 decades of it on the
512^2 decaying preset it was tuned on. Presets: all now set `cbAutoDiss` explicitly (they
must, or a preset switch would inherit the last one's state); every one is ON except 2D
`tearing`, whose whole point is a QUOTED eta against a linear reference growth rate — the
same argument that makes it lock hyper. `decay` and `collision` lost their `prep:
autoDiss()` for `prep: autoDissSeed()` (collision keeps `autoZDiss()`; the 3D z-diss
button is untouched). Item 3 (KH) is fixed by construction: nothing in the rule reads the
forcing sliders.

Replace the one-shot "auto" button with a tickbox (ticked by default) that continuously
sets diss from the **measured amplitude at a scale a few times k_diss** (cf. the rmhdgpu
implementation on GitHub — check its exact rule). This also fixes item 3 (KH) for free,
since a measured amplitude needs no assumption about where energy comes from. Manual
slider stays live when unticked.

### 7. Rescale the diss slider

**IMPLEMENTED 2026-08-08** — the range is now recomputed from the live hyper / resolution
/ box by `dissRangeSync()`, called from `syncCommonLabels` (the one function every path
that can change them ends in). Top = Re ~ 1 at the box scale, `nu_top = k_1^(1-2*hyper)`
(exactly 1 in a 2pi box). Bottom = `DISS_DECADES_BELOW` = 3 decades under `nu_marg` (see
item 6), where the cascade stops terminating inside the retained band. One sweep is then
viscous → eps-independent dissipation → numerically unresolved. Three details that make
it safe: a range `<input>` SANITIZES an assigned value against min/max/step, so
`presetWrite` opens the range to `DISS_LG_OPEN` before writing and the following
`syncLabels` narrows it again; the narrowed range is widened OUTWARD to whatever value is
then stored, so a re-range never moves the physical value (checked for every preset's
rDiss in `checks.js` §7); and both ends are snapped to the 0.05 step grid while every
code-written value goes through `dissWriteLog`, which quantizes to the same grid — so
nothing ever snaps to a value nobody asked for. Measured ranges: 2D forced 256^2 hyper 4
[-15.55, 0] holding -13; 2D kh/tearing 512x128 wide hyper 1 [-5, 0.35] holding -3.5 / -3;
3D forced [-13.30, 0] holding -10.65; 3D collision [-11.10, 0] holding its -8.05 seed.

Current range 10^-20…10^-1 (`common.js:1613`) mostly spans irrelevantly-small values.
Scale it so a user can scan smoothly from Re~1 down to below the auto-diss level, and
see in one sweep: viscous flow (Re~1) → turbulence with eps-independent dissipation
(zeroth law) → numerical instability when diss is too low. The slider is then itself a
demo instrument.

### 8. Spectrum fit line: settable index and amplitude

**IMPLEMENTED 2026-08-08** — the guide is now `E = A k^p` with per-CARD controls beside
`sq` / `sd`: a mode select (`pin to field` / `set A` / `off`, default = the old behaviour)
and two small number boxes for `p` (default -1.667) and `A`. `ChartCard.build` grew a
`k: "num"` option kind and a `vis(vals)` predicate so the two boxes hide with the line;

default) and SNAPS anything within `FIT_SNAP` of -5/3 or -3/2 to the exact fraction, which
`fitLabel` then prints as the fraction — so the default legend still reads `k^-5/3` and a
1.5 reads `k^-3/2`, while anything else is drawn and labelled as the number it is.
`fitAnchor` inverts `A = E(kA) kA^-p` at the same anchor the fixed guide used (the first
drawn ⊥ point at or above the forcing shell's upper edge); in `set A` mode an empty or

now gated on the ⊥ series having set the axis). The `waiting…` / empty paths are
unchanged (the anchor is 0 and no line is drawn).

The k^-5/3 guide (`common.js:973–1001`) becomes a fit line with a settable spectral

### 9. New IC for the AW collision: sinusoidal z±

**IMPLEMENTED 2026-08-08** — a new 3D-only IC preset `IC_SINE` ("sinusoidal z± packets
(exact interaction)"), added through `ctrlGrpIC`'s `presets` list. What is stored is the
POTENTIAL, so a field that is a pure sine needs a cosine potential:
`zeta+ = -cos(k1x x)/k1x`, `zeta- = +cos(k1y y)/k1y` give `z+ = a+ yhat sin(k1x x)` and
`z- = a- xhat sin(k1y y)` after `icZetaFields` normalizes each to max|grad zeta| = its own
amp slider (the 1/k prefactors are what make that exact). Each field alone is an exact
ideal solution; together they interact through exactly one beat. It is a PACKET preset in
every other respect — `icIsPacketIC` is the single predicate `applyIC`, `icInfoLine` and
`icSyncRows` all use, so the `icGaussZ`/`packetGeom` envelopes, sigma_z, the chi readout,
the trackers and the meeting time are the letters' machinery unchanged; its k_perp in the
chi line is the mode's own `1/k1 = Lx/2pi` (the one case where that is exact rather than
an estimate). `icLetterZeta` and `icSineZeta` now share `icZExtrude` for the envelope
multiply, so no clone group was created. The editor/paint path is unaffected: `rowDraw`
stays hidden (only `custom` shows it) and `rowSigZ` / the amp sliders come on, which
`bootstub` asserts. The collision preset's DEFAULT IC is untouched; this is an extra
dropdown entry, and the preset's hint points at it.

Add a `z± = sin x, sin y` (× gaussian z-envelope) IC option to the collision setup —
the classic exact-interaction configuration, complementing the letter packets of
DEMOS_PLAN Phase D.

## Tutorial presentation — decision

**Chosen: guided in-app demos** (option 1): sequences you work through inside the app,
with links/buttons that jump to specific presets *and parameter values*, and, at the end
of each demo, options for what to do next — the next demo in sequence OR related demos.
Rejected: a standalone markdown document (not relaxing for a casual user).

**Demo builder**: author demos as text with a light syntax for the two live element
types — links that navigate (preset/demo deep links) and param setters (set one or more
controls to given values, optionally then `applyControls`/`autoDiss`). The existing
`?demo=` registry + `presetWrite` machinery (`common.js:1750–1800`) is the natural
substrate: a demo page is a hint-panel-like card rendering the text, where a param-set
element is just a partial `set` record applied live. Design TBD before any
implementation.
